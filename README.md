# CGL 분기 가동계획 (웹)

도금 1·2CGL 분기 일별 가동계획을 **브라우저 안에서만** 계산하는 정적 웹페이지입니다. 설치·로그인·서버가 필요 없고, 올린 엑셀은 어디에도 전송되지 않습니다.

## 화면
- **대시보드(조회, 모든 사람)** — https://jmin6035.github.io/gadong-plan-web/  
  게시된 최신 계획을 암호로 엽니다(기기별 한 번, 기억). 라인 현황·KPI·일별 생산·부하·M/C 일정·부서별 생산·간트.
- **계획 계산(담당자)** — `plan.html`  
  ① 가동_판매자가재 엑셀 하나 선택(선적 일정이 바뀐 달만 배선일정분석 파일 추가) → ② 조건 확인 → ③ 계산 → ④ 게시(암호화) → 모두의 대시보드 갱신.  
  실적 반영 재계획도 여기서 합니다.

## 계산 방식 (Python 파이프라인 v30과 동일)
1. 판매계획(부서·권역·용도·고객군)·자가재(섹션) → 목적지 단위 수요. 수출은 권역 물량 × 배선일정 선적창으로 마감일 분할
2. MILP 1단계: M/C 횟수 최소(정기수리 후 재가동 강종 변경은 M/C 환산 가중)
3. MILP 2단계: M/C 횟수·재가동 판단 고정, 선생산(톤·일) 최소. 허용오차 0(PC마다 같은 결과)
4. 평준화 LP: 강종 일정 고정 후 하루 최대 여유시간 최소 → 선생산 최소
5. 목적지 순차 배정, 엑셀·간트 작성, 전환·선생산 이유 문구 자동 생성

검증: 2026년 4분기 입력으로 Python 확정안 v30과 수요 항목 168건·버킷 70개 톤 단위 일치, MILP 목적함수(7.1157 / 1,156,913.67)·전환 일정·선생산 3,323.6t·월별 부하 일치.

## 입력 해석 규칙
- 행 번호가 아니라 `상세` 열의 합계행 키와 라벨로 행을 찾습니다(`engine/params.js`의 `SALES_SPEC`).
- 합계행과 반영 행의 합이 다르면, 또는 규칙에 없는 행에 물량이 있으면 경고합니다(양식 변경 감지).
- 월 열은 머리행의 "N월" 라벨로 찾으므로 분기가 바뀌어도 그대로 씁니다.

## 파일 구성
| 파일 | 역할 |
|---|---|
| `plan.html`, `style.css`, `app.js` | 계획 계산 화면(담당자), 엑셀·간트 작성, 게시 |
| `worker.js` | 계산 전용 Web Worker(입력 해석 + 최적화) |
| `engine/params.js` | 기본 파라미터(속도·더미·정기수리 등)와 판매계획 해석 규칙 |
| `engine/parse.js` | 입력 엑셀 해석 |
| `engine/model.js` | 버킷·MILP·평준화 LP·목적지 배정 |
| `engine/report.js` | 분석·이유 문구·엑셀 |
| `engine/gantt.js` | 월별 간트 canvas |
| `engine/replan.js`, `engine/actual.js` | 롤링 재계획, 실적 엑셀 양식·해석 |
| `index.html`, `dashboard.js/.css` | 대시보드(조회) |
| `engine/crypto.js` | 게시 파일 암호화(AES-GCM) |
| `engine/sail_default.js` | 기본 배선일정(배선일정 파일을 안 올리면 사용) |
| `vendor/` | HiGHS(highs-js 1.15.3, MIT), ExcelJS(MIT) — 외부 CDN 없이 동작 |
| `test/` | Node 검증 스크립트(입력 데이터는 저장소에 없음) |

## 로컬 실행
```bash
python -m http.server 8000   # 이 폴더에서 → http://localhost:8000
```
`file://`로 직접 열면 Web Worker가 막히므로 간단한 서버가 필요합니다.
